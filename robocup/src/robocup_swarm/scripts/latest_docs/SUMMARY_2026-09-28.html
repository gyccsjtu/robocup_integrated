① 检测误差压到 0.3m 以下 / 做融合 —— 剂量-效应曲线已定死

给接 YOLO 的硬指标：有效 σ ≤ 0.3m。 多机融合（MULTI_UAV_FUSE）实测几乎没生效 —— 日志里「融合 1 路观测」占绝大多数， 同一时刻只有 1 架在盘旋，根本没有共视；要把 0.6 降到 0.3 需要 N≥4 架共视，代价是搜索吞吐。 别指望融合救 0.6m 的检测。

② 确认失败加退避重试 —— 已部署并验证机制在工作

实现：swarm_agent 订阅官方 /find_actor_<i>，检测到「官方重置」即计数， 达到 CONFIRM_RESET_MAX 后放弃该目标去搜别处，BACKOFF_COOLDOWN 后回来， 期间用 RESET_DECAY 衰减计数（避免一次抖动就永久拉黑）。

噪声压测轮实测：官方重置 804 次、触发退避 6 次 —— 机制确实在触发， 但因目标数 = 机数（6:6 无余量），退避带来的收益被「少一架在搜」抵消， 属于保险丝而非加速器：保留默认开启，别指望它提分。

3. 最大收益来源：三个「飞机根本没在飞」的根因

先给 safety_monitor.py 加了轨迹诊断（4Hz 全机位姿 → 均速 / 静止占比 / 扫描率 / 覆盖率），才看到真实状态：

机      路程    均速     静止时间
iris_1   10m    0.04   100%
iris_2  277m    1.23    34%
iris_3  218m    0.97    25%
iris_4   42m    0.19    89%
iris_5   44m    0.19    90%
iris_6   18m    0.08    99.8%
全机      —     0.47    72.9%     扫描率 87.9 m²/s（理论 720）

根因 1：A* 起点越界 → 永久停摆

飞机被推到 y≈69，而 A* 栅格 y_max=65 → START_OUT_OF_BOUNDS 每 2s 刷一次、刷满整轮， _plan_path() 返回 False → 无 path → 速度指令恒为 0 → 原地趴一整轮。
修：PLAN_FALLBACK=1 —— 任何失败先把起点拉回最近自由格重试，再不行退化为直飞航点串（宁可可能穿楼，也不能不动）。

根因 2：manager 误判「搜完了」就降落，落地自锁

一架没拿到格 + tracker 空 + _left_actors 未更新 → 判定全部完成 → _publish_land()， agent 触地后自己 arm_srv(False) 上锁，之后再也起不来。
修：AUTO_LAND=0（真跑完官方会打 Mission finished 结束整轮）；守卫侧改为 armed 就先 disarm 再 arm （此前只调 CommandBool(True)，而车本来就是 armed → 空操作，19 次全无效）。

根因 3：PX4 Offboard-Loss → AUTO.LAND（最致命）

新写的 state_watch.py 抓到铁证：uav_2 armed=True mode=AUTO.LAND，紧接着 iris_2 落地 z=0.1。 机制是 mavros→PX4 的 UDP 抖动超过 Offboard-Loss 判定，COM_OBL_ACT 默认 0=Land。
修：COM_OBL_ACT=1(Hold) + NAV_DLL_ACT=0 + NAV_RCL_ACT=0， 外加模式看门狗（z>0.3 且 mode≠OFFBOARD → 3s 内拉回）。

注：COM_OF_LOSS 在本版 PX4 读写都返回 False（参数不存在），判定窗口改不了，靠 Hold + 看门狗兜住。

4. 最新成果：LOS 感知 next-best-view（NBV）

做法 —— 和已被证伪的 W_EDGE 的本质区别

  1. 预计算可见集：启动时一次性算出每个候选视点真正能看见哪些格（航点为视点、20m 半径、LineOfSight 不穿楼）。 实测 518 个视点，平均可见 17.8 格（3~25）。
  2. 可见增益：min(1, 陈旧格计数 / 12)。楼背后的区域从任何视点都看不见 → 不会被假装搜过； 拐个弯能看见一大片死角的地方增益自然最高 —— 这才是「绕到楼后面看」。 （初版写成「平均陈旧度」导致任何视点增益恒为 1.0，和当初拍卖 gain 被距离项压死是同一个 bug，已修。）
  3. 派单即承诺（关键）：某格一派给某架机，立刻把它可见集的 last_seen 刷成当前时间 → 别机再看同一片增益≈0 → 队形自动散开。这是次模贪心的标准写法，正是 W_EDGE 缺的那块。

6. 风险与待决策

⚠️ 唯一新增风险：NBV 提速后高度超调抬头。 机队均速 1.23 → 1.84 m/s，nbv_d 一轮 iris_4 冲到 5.63m（5.2% 采样 >5.0m）， 而此前 13 轮 max_z 一直稳在 4.4~5.0。6m 是一票否决（score=0 且任务终止），余量只剩 0.37m。

高度护栏属于冻结项，我没有动。建议加一道 z>5.0 的二次保险 （在 _send_vel 唯一出口加强制快降 + 水平缩速），但会轻微牺牲速度 —— 需要你拍板。

下一步（按性价比排序）

  1. 高度二次保险（待决策）+ NBV 再补 2~3 轮确认，同时盯 max_z。
  2. 33 个死角格：给「路过可见」单独建模 —— 沿飞行路径采样而非只采样航点， 这些格从任何航点都看不见，只能靠路过。
  3. 接 YOLO：门槛是有效 σ ≤ 0.3m；接之前先确认真实检测噪声的相关性模型（必须按 OU 相关建模，i.i.d. 结论是错的）。
  4. 单轮噪声 ±165 分，任何结论都要 ≥5 轮取中位数；快筛只用低方差指标 （用时 / T4 / 扫描率 / air / low），不要用覆盖率（在快轮上是反向的）。

9. 踩过的工程坑（下次直接避开）

  • ssh 重试会把「启动批次」重复执行 5~6 遍 → ROS new node registered with same name → 所有重份被 shutdown，整轮报废（18:18 那轮白跑）。 修：启动类命令走 flock 单实例启动器 launch_once.sh。
  • pkill -f 会误杀自己的 ssh 会话（命令行里含同样字符串）→ 改用 ps + awk 取 PID 逐个 kill（kill_dup.sh）。
  • 区域云 sshd 随机 Connection closed，与命令内容无关 → 本地 sshr.sh（重试 10 次）；scp 也要重试循环；长命令更容易掉 → 写成脚本 scp 上去再执行。
  • 给 manager 打补丁要按函数体范围正则切片，同名片段会在别的函数先命中；改完必须 py_compile。
  • 机队齐全的唯一可靠判据：ls /tmp/px4-sock-* | wc -l == 6；每轮前跑 prelaunch_cleanup.sh。
